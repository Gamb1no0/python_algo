# Хеш-таблица

В `hash_table.py` находится класс `HashTable`, в `test_hash_table.py` — тесты.

## Как работает

Данные хранятся в списке ячеек. Каждая ячейка — тоже список, а внутри лежат пары в виде `[ключ, значение]`. Для хранения используются только `list`, без `dict`, `set` и кортежей.

Номер ячейки считается как `hash(key) % capacity`. Встроенный `hash()` только вычисляет хеш ключа. Хранение, поиск, удаление и расширение сделаны вручную. Ключ должен поддерживать `hash()`, например число или строка. Его хеш и правила сравнения не должны меняться, пока ключ находится в таблице. Значения могут быть любыми, в том числе `None` и списками.

Если несколько ключей попали в одну ячейку, храним все пары в её списке. Это разрешение коллизий методом цепочек. При поиске перебираем пары в нужной ячейке и сравниваем ключи, поэтому одинаковые хеши не мешают различать разные ключи.

При вставке сначала проверяем, есть ли ключ. Если есть — заменяем значение. Иначе добавляем новую пару. При удалении убираем только пару с нужным ключом и уменьшаем количество элементов.

Если после добавления нового ключа отношение количества элементов к числу ячеек превысит 0.75, заранее увеличиваем число ячеек вдвое. Все существующие пары распределяем заново: остаток от деления на новый размер может измениться. При замене значения таблица не расширяется.

Таким образом, поиск проверяет ту же ячейку, в которую вставлялся ключ. Расширение сохраняет это правило, потому что пересчитывает расположение всех пар.

## Операции

| Вызов | Что делает |
| --- | --- |
| `insert(key, value)` | Добавляет пару или обновляет значение |
| `get(key, default=None)` | Возвращает значение, а если ключа нет — default |
| `delete(key)` | Удаляет пару и возвращает её значение; если ключа нет — KeyError |
| `table[key]` | Возвращает значение; если ключа нет — KeyError |
| `table[key] = value` | Добавляет или обновляет пару |
| `del table[key]` | Удаляет пару; если ключа нет — KeyError |
| `key in table` | Проверяет наличие ключа, даже если его значение — None |
| `len(table)` | Количество хранимых пар |
| `table.capacity` | Количество ячеек |
| `keys()`, `values()`, `items()` | Возвращают списки ключей, значений и пар |

Порядок элементов при обходе не гарантируется. `items()` создаёт новые списки пар, сами ключи и значения не копирует глубоко. После удалений таблица не уменьшается автоматически.

## Сложность

Пусть n — количество пар, m — число ячеек. При равномерном распределении хешей вставка, поиск и удаление занимают в среднем O(1), потому что списки внутри ячеек короткие. Для вставки это оценка в среднем по серии операций с учётом расширений.

Если все ключи попали в одну ячейку, операции с ключом занимают O(n). Одно расширение занимает O(n + m): создаём новые ячейки и переносим пары. Размер удваивается, поэтому расширять таблицу приходится всё реже. `len()` и `capacity` работают за O(1), а `keys()`, `values()` и `items()` — за O(n + m).

Память таблицы — O(n + m). При обычном росте m пропорционально n, но после большого числа удалений или при большом начальном размере пустые ячейки остаются. Расширение временно требует ещё O(n + m) памяти. Здесь вычисление хеша и сравнение ключей считаем за O(1); для длинных строк или пользовательских классов их стоимость может быть больше.

## Пример с коллизией и расширением

Создадим таблицу с 4 ячейками. Для небольших положительных целых чисел Python `hash(key)` равен самому числу.

| Действие | Что происходит |
| --- | --- |
| `insert(1, "один")` | 1 % 4 = 1, ячейка 1: `[[1, "один"]]` |
| `insert(5, "пять")` | 5 % 4 = 1, ячейка 1: `[[1, "один"], [5, "пять"]]` |
| `insert(9, "девять")` | 9 % 4 = 1, в той же ячейке теперь три пары |
| `insert(5, "ПЯТЬ")` | Обновляем вторую пару. Количество элементов остаётся 3 |
| `insert(2, "два")` | Будет 4 / 4 > 0.75, увеличиваем число ячеек до 8 |

После расширения и добавления ключа 2:

```text
ячейка 1: [[1, "один"], [9, "девять"]]
ячейка 2: [[2, "два"]]
ячейка 5: [[5, "ПЯТЬ"]]
остальные ячейки пустые
```

При `delete(1)` из ячейки 1 удалится только `[1, "один"]`, а `[9, "девять"]` останется доступной.

## Как запустить

Из папки `homework_3/hash_table`:

```bash
python3 hash_table.py
```

Запустится пример с коллизиями, заменой значения, расширением и удалением.

Тесты из той же папки:

```bash
python3 -m unittest -v
```

Проверяются основные операции, отсутствующие ключи, `None`, обновление, удаление из середины цепочки, расширения и повторная вставка. Для коллизий есть отдельный класс ключей с одинаковым хешем. Ещё проверяются хранение только в списках и работа с 2000 элементами. Используется стандартный unittest, ничего устанавливать не надо.
