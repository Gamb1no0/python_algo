# Merge lists

В `merge_lists.py` находятся класс узла `ListNode` и два решения. В `test_merge_lists.py` — тесты.

У узла есть значение `val` и ссылка `next` на следующий узел. В функции передаются головы двух отсортированных списков, пустой список — это `None`. Функции возвращают голову объединённого списка.

## Как работает

Сравниваем первые ещё не взятые узлы обоих списков и присоединяем меньший к результату. При равенстве берём узел из первого списка. Сдвигаем указатель в выбранном списке и повторяем. Когда один список закончился, присоединяем оставшуюся часть другого целиком.

Это работает, потому что оба списка уже отсортированы. Минимальный из оставшихся элементов всегда находится в начале одного из них. Значит, каждый раз мы выбираем следующий элемент в правильном порядке.

### С фиктивным узлом

В `merge_with_dummy` создаётся один служебный узел `dummy`. Сначала `tail` указывает на него, а выбранные узлы добавляются через `tail.next`. Так первый элемент присоединяется точно так же, как остальные. В конце возвращаем `dummy.next`, сам фиктивный узел в результат не входит.

### Без фиктивного узла

В `merge_without_dummy` сначала отдельно выбираем голову результата из двух первых узлов. Потом присоединяем остальные тем же способом. Если один из списков пустой, сразу возвращаем другой. Дополнительные узлы вообще не создаются.

В обоих решениях используются исходные узлы: меняются только ссылки `next`, значения не копируются в новые узлы. Поэтому для повторного запуска на тех же данных нужно заново создать исходные списки. Сторонние библиотеки не используются.

## Сложность

Оба способа работают за O(n + m), где n и m — длины списков. Каждый выбранный узел обрабатывается один раз, оставшаяся часть присоединяется одной ссылкой.

Дополнительная память — O(1): нужны только несколько указателей. В первом способе ещё создаётся один фиктивный узел. Оба решения используют цикл, без рекурсии. Здесь сравнение значений считаем за O(1).

## Пример

Первый список: `1 → 2 → 4`, второй: `1 → 3 → 4`.

В таблице показаны уже выбранные узлы, а в последней строке — результат после присоединения остатка.

| Шаг | Что берём | Готовая часть |
| --- | --- | --- |
| 1 | 1 из первого списка | 1 |
| 2 | 1 из второго списка | 1 → 1 |
| 3 | 2 из первого списка | 1 → 1 → 2 |
| 4 | 3 из второго списка | 1 → 1 → 2 → 3 |
| 5 | 4 из первого списка | 1 → 1 → 2 → 3 → 4 |
| 6 | Первый список закончился, присоединяем остаток второго | 1 → 1 → 2 → 3 → 4 → 4 |

С фиктивным узлом на первом шаге записываем ссылку в `dummy.next`. Без него первый выбранный узел сразу становится `head`. Дальше порядок выбора одинаковый.

## Как запустить

Из папки `homework_2/merge_lists`:

```bash
python3 merge_lists.py
```

Запустится пример из задания для обоих способов. Каждый выведет `[1, 1, 2, 3, 4, 4]`. Преобразование в обычный список сделано только для вывода, сами функции слияния возвращают узел.

Запуск тестов из той же папки:

```bash
python3 -m unittest -v
```

Каждый случай проверяется для обоих способов. Есть пустые списки, по одному элементу, повторы, отрицательные числа, разная длина, разные порядки чередования и слияние 10000 узлов. Проверяется не только порядок значений, но и то, что все исходные узлы попали в результат ровно один раз, их значения не поменялись и циклов нет. Используется стандартный unittest, ничего устанавливать не надо.
